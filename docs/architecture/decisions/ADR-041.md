# ADR-041: Dual-path Qobrix MCP (Mode D + Mode C on one process)

**Status**: Accepted  
**Date**: 2026-08-22  
**Depends on**: [ADR-039](ADR-039.md), [ADR-040](ADR-040.md)  
**Scope**: `qobrix-crm-mcp` HTTP server, Apache intranet proxy, `matrix-digital-employees` MCP client

## Context

Qobrix MCP historically used a single global `QOBRIX_MCP_AUTH` env var. Production
ran **Mode D** (`oauth-claude`) on `/mcp` for Claude.ai, Dust.tt and Cursor.
Matrix Digital Employees needs **Mode C** (no Bearer; per-user vault via
`/connect` URLs in tool results). Mode cannot be inferred from the HTTP request
alone — both client types arrive without `Authorization` on first contact.

## Decision

### D1 — Mode per endpoint (dual HTTP)

One `qobrix-crm-mcp` process with `QOBRIX_MCP_DUAL_MODE=1`:

| Public path | Auth mode | Clients |
|-------------|-----------|---------|
| `/qobrix-crm/mcp` → `/mcp` | Mode D | Claude, Dust, Cursor |
| `/qobrix-crm/mcp-c` → `/mcp-c` | Mode C | Digital Employees, ragchat |

Mode C browser routes (`/connect`, `/oauth/callback`) and Mode D PRM register
unconditionally when dual mode is on.

### D2 — Request-scoped auth in ALS

`request-context.ts` carries `authMode` per MCP request so `client.ts` and
`tools/session.ts` use `getRequestAuthMode()` instead of the global env.

### D3 — Digital Employees as Mode C client

- Register Qobrix at `…/qobrix-crm/mcp-c` with `auth_mode = server_managed`.
- Sign `X-Chat-*` identity headers with shared `QOBRIX_MCP_IDENTITY_SECRET`
  (vault key `{platform}:{sso_user_id}`).
- **No** platform `AUTH_REQUIRED:` protocol — relay the MCP server's own tool
  result text (Markdown connect link) verbatim.

### D4 — System directives (operator-owned prompt fragments)

Hardcoded runtime instructions move to `employees.system_directives` jsonb and
the **System** tab in the employee editor. Empty string disables a directive;
absence uses the seeded default.

## Consequences

- Apache: proxy `/qobrix-crm/mcp-c`, `/connect`, `/oauth/callback` before `/mcp`.
- `QOBRIX_MCP_IDENTITY_SECRET` must match on MCP host and in Lovable secrets.
- ADR-040 § D4 (`AUTH_REQUIRED` agent contract) is **superseded** for
  `server_managed` servers; `oauth_user` servers may still use client OAuth.
