# ADR-020: Per-tenant, per-locale UI label/terminology overrides (tenant_key axis + `App.*` namespace + Hungarian)

**Status**: Accepted
**Date**: 2026-06-02
**Extends**: [ADR-012](ADR-012.md) (dedicated CDL project, separate from SSO), [ADR-016](ADR-016.md) (canonical-into-CDL for matrix-pipeline), [ADR-008](ADR-008.md) (5-level scope hierarchy)
**Scope**: CDL project `ofzcokolkeejgqfjaszq` (`reso_field_descriptions` / `reso_lookup_value_descriptions`, `reso-dd-descriptions` read EF, `mls-sync` write EF) + `matrix-pipeline-2-0` FE. **Does not touch SSO (`xgubaguglsnokjyudgvc`).**

## Context

Matrix Pipeline 2.0 renders canonical RESO labels through `<ResoFieldLabel>` /
`<ResoLookupValue>`, whose resolution chain already prefers the CDL corpus
`DisplayName` (served by the public `reso-dd-descriptions` EF) over any FE
fallback. The corpus is keyed by `(field, locale)` and carries the tooltip
`description` plus lookup-value `DisplayValue` / `Definition`.

Two product needs were outstanding from the Week-0 i18n task:

1. **A third UI locale (Hungarian)** alongside the existing EN/RU — the HU + KZ
   offices author directly in Dash, and the platform UI must localise to `hu`.
2. **Admin-configurable terminology** — tenant admins must be able to *rename*
   any UI noun (e.g. "Transaction" → "Contract", "Property" → "Listing") **and**
   *translate* it per locale, without a code change and without mutating the
   RESO data model, EF `resource` names, `pageKey`/route identifiers, or the
   canonical corpus keys that the schema/ingestion rely on.

The corpus is already `(field, locale)`-keyed, so a per-tenant override layer is
a natural extension rather than a new subsystem. The original FE→CDL contract
for this lives in `matrix-pipeline-2-0/docs/cdl-ef-contracts/reso-label-overrides.md`.

## Decision

**Add a `tenant_key` axis to the CDL description tables and merge tenant
overrides over the global RESO truth at read time; expose a curated `App.<Term>`
key namespace for UI nouns that have no RESO resource; register `hu` as a full
third app locale.**

### 1. Storage (CDL `ofzcokolkeejgqfjaszq`)
- `reso_field_descriptions` and `reso_lookup_value_descriptions` gain
  `tenant_key text NOT NULL DEFAULT ''`. `''` means **global RESO truth**; a
  non-empty value scopes the row to one tenant.
- Composite PKs become `(field, locale, tenant_key)` and
  `(lookup_name, standard_value, locale, tenant_key)` respectively; a partial
  index covers `WHERE tenant_key <> ''`.
- Curated UI nouns with no RESO resource are seeded **globally** under an
  `App.<Term>` key namespace (`App.Pipeline`, `App.Transaction`, `App.Settings`,
  the `App.Section*` sidebar headings, …) with `source='vendor_extension'`,
  seeded for `en` + `ru` + `hu`. RESO-backed nouns reuse existing
  `Resource.<X>` / `<Resource>.<Field>` keys.

### 2. Read merge (`reso-dd-descriptions` EF)
- Accepts an optional `tenant` query parameter. Resolution is a three-layer
  overlay per `(field, locale)`: **global `en` baseline → global requested
  locale → tenant-specific requested locale**. Empty override strings are
  treated as "no override" and fall back to the layer below.
- Global responses (no `tenant`) stay CDN-cacheable; tenant responses are
  `private, no-store` so a relabel is visible immediately.

### 3. Write surface (`mls-sync` EF, resource `reso_label_override`)
- `list-resource` (global + this tenant's override side by side),
  `upsert-resource` (single- or **multi-locale** `locales:{ en, ru, hu }` map),
  `delete-resource` (reset a field's overrides). The EF force-injects
  `tenant_key = caller.tenantId` + `source='team_override'`, rejects keys/values
  absent from the global corpus, and emits a `HistoryTransactional` row
  (`change_type` Created/Updated/Deleted) per
  [wiki/integration.md#history-emission](../../product-specs/matrix-pipeline/wiki/integration.md#history-emission).

### 4. Authorization
- The write path is gated by the **SSO scope claim** (`global` / `org_admin` /
  `system_admin`): the FE hides the editor for non-admins and the CDL
  `mls-sync` EF (`verify_jwt:false` + ES256/JWKS) re-checks the scope before
  writing. matrix-pipeline does **not** register `pipeline:reso_label_override:*`
  keys in the legacy SSO permission catalog — it authorises pages/actions via
  its own `role_configurations` table + the scope claim (see
  [wiki/architecture.md#app-private-state](../../product-specs/matrix-pipeline/wiki/architecture.md)).

### 5. FE
- Full `hu` locale (registered in i18n, complete `hu.json`, language switchers).
- A `Term`/`useTerm` resolver reads the merged corpus for `App.*` / `Resource.*`
  keys so sidebar nouns and page titles relabel/translate live; identifiers stay
  canonical.
- Settings → **Translations & Labels** (admin-gated) edits a label and its EN/RU/HU
  translations side by side; saving fans out one multi-locale `upsert-resource`
  and invalidates the `reso-dd-descriptions` cache for all locales.

## Consequences

- **Positive**: one store serves three purposes (official corpus, per-tenant
  terminology, additional UI translations); no new table; no app-local override
  store; the RESO data model and all canonical identifiers are untouched;
  Hungarian (and any future locale) reuses the same axis; relabels are audited.
- **Negative / cost**: the `tenant`-scoped read response is uncacheable at the
  CDN, so authenticated label reads hit the origin (mitigated by React Query
  caching keyed on `(locale, tenant, corpus version)`); the FE list editor fans
  out one `list-resource` call per locale to populate the side-by-side editor.
- **Boundary**: every artifact lives in the **CDL** project. SSO only issues the
  JWT + scope claim that the CDL EF verifies. No override data is stored in SSO.

## Alternatives considered

- **App-local override table on the pipeline app DB (`wckwfbbqiupvallmhqbu`)** —
  rejected: would split label truth across two projects, duplicate the corpus,
  and break the single-source-of-truth that `reso-dd-descriptions` already
  provides; cross-locale fallback would have to be reimplemented client-side.
- **FE-only i18n keys for the curated glossary (no CDL rows)** — rejected: could
  not be edited by tenant admins at runtime and would not cover the full RESO
  field/resource/lookup corpus.
- **Registering `pipeline:reso_label_override:*` in the SSO permission catalog** —
  rejected: the pipeline app does not consume that catalog for authorization
  (it uses `role_configurations` + scope), so the keys would be inert; the scope
  check at the EF is the real enforcement point. Documented as a deliberate
  divergence.
