# ADR-028: CRM-internal Commission Engine (ERP-lite) — app-private, role-config + JWT-scope authz, Finance-ERP reconciliation

**Status**: Accepted (architecture); implementation lands via matrix-pipeline Week 5 (Lovable app-DB schema/UI + Cursor Finance-ERP EFs)
**Date**: 2026-06-10
**Deciders**: Pipeline team + Platform team (CDL owners)
**Related**: [ADR-016](ADR-016.md) (`cdl-write`/`cdl-read` dispatchers), [ADR-025](ADR-025.md) (no `sso_app_permissions` for matrix-pipeline; `role_configurations` page-keys + CDL JWT-scope), [ADR-026](ADR-026.md) (event-sourced transaction phase on canonical homes; `cdl-listing-lifecycle`), [ADR-012](ADR-012.md) (dedicated CDL project / app never holds the CDL service-role key), [ADR-018](ADR-018.md) (SSO issuer + Supabase TPA for own-DB apps), [wiki/commission-engine.md](../../product-specs/matrix-pipeline/wiki/commission-engine.md), [wiki/integration.md#finance-erp-commission](../../product-specs/matrix-pipeline/wiki/integration.md), [phases.md Week 5](../../product-specs/matrix-pipeline/phases.md#week-5), [requirements.md](../../product-specs/matrix-pipeline/wiki/requirements.md) (FR-FNL-12, FR-TM-13, FR-REP)

## Context

`matrix-pipeline` 2.0 Week 5 requires a Commission Engine: per-deal forecast GCI,
attributed operational costs, deal-level P&L, per-broker compensation under
published rules, and reconciliation against the external Finance ERP at close
([wiki/commission-engine.md](../../product-specs/matrix-pipeline/wiki/commission-engine.md)).

Three prior decisions constrain how it must be built:

1. **Canonical RESO has no deal-level P&L or commission-ledger resources.** The
   canonical `transaction-lifecycle.md` Non-goals say explicitly: *"No commission
   ledger; project flavours encode that."* `TransactionManagement` is the bare
   4-field RESO header (ADR-025/ADR-026) and gains no economics columns.
2. **matrix-pipeline does not participate in `sso_app_permissions`** (ADR-025
   Decision #3). It authorizes pages via `role_configurations` page-keys (app DB,
   `useRoleConfig` + admin fallback) and gates CDL reads/writes on **SSO JWT scope**
   (`SSO_READ_SCOPES`/`SSO_WRITE_SCOPES`). Writing `pipeline:commission:*` rows into
   SSO would be dead data the app never reads.
3. **The app never holds the CDL service-role key** (ADR-012). Any CDL write
   (including the `HistoryTransactional` audit event on reconciliation) goes through
   an Edge Function with service-role inside.

## Decision

### 1. The Commission Engine is app-private ERP-lite (escape hatch), never CDL/SSO

All Commission Engine state lives in the **Pipeline App DB** (Lovable-managed),
not in CDL and not in SSO. It is an explicit project-flavour deviation from
canonical RESO ([wiki/architecture.md#escape-hatch](../../product-specs/matrix-pipeline/wiki/architecture.md)).
App-private tables (Pattern B RLS in the App DB), authored by Lovable:

| Table | Role |
|---|---|
| `deal_cost_event` | one attributed operational cost (legal/marketing/conference/showing/negotiation/client_care/research/other); manual or auto-derived from a tagged `Activity` (FR-ACT-10) |
| `cost_rate_card` | reference rates applied when a cost event carries no custom amount |
| `commission_rule` | rule definitions (`PercentOfGCI`/`TierBased`/`SplitBased`/`BaseAndBonus`/`TeamOverride`/`Composite`) + params/scope/priority |
| `deal_pnl` | per-`transaction_key` forecast GCI, attributed costs, net margin; plus `actual_gci`/`variance` written server-side on reconciliation |
| `broker_compensation` | per-`member_key` payout breakdown on a deal |

All references to RESO keys (`transaction_key`, `member_key`, listing `listing_key`)
are **logical pointers across projects**, not DB foreign keys to CDL. Forecast base
follows FR-FNL-12 precedence: `TransactionManagement` offer amount (a) > `SavedSearch`
budget mid-point (b); switching the base emits a `HistoryTransactional` row.

### 2. Authorization = `role_configurations` page/action keys + JWT scope; NO SSO permission keys

Consistent with ADR-025 Decision #3, the Commission Engine adds **no
`sso_app_permissions` rows**. The Week-5 plan text "C1 — add SSO permission keys
`pipeline:commission:read|write|admin`" is **intentionally NOT implemented as
written** (see KB divergence). The *intent* (gate commission features by role) is met
in two existing layers:

- **App layer**: the P&L tab sits under the existing `transactions` page-key; the
  Reports surface uses the `reports` page-key; the admin-only `commission_rule`
  editor is gated by a `role_configurations.actions` **action key**
  (`commission:admin`) via `useRoleConfig().canPerformAction`. Page/action seeding is
  a Lovable app-DB migration (the established `array_agg` dedup pattern), not an SSO
  change.
- **EF layer**: the `finance-erp-webhook` write-path verifies the SSO ES256 JWT and
  gates on JWT **scope** (`SSO_WRITE_SCOPES`, broker scopes allowed), the same model
  as `cdl-write`/`cdl-listing-lifecycle`.

### 3. Finance-ERP reconciliation runs through two app EFs (Cursor-built, deployed via MCP)

`deal_pnl`/`broker_compensation` forecasts are app-private and Lovable-computed.
**Actuals** arrive from the external Finance ERP and are written server-side:

- **`finance-erp-webhook`** (App DB project EF; `verify_jwt=false` + in-code SSO/secret
  verification; service-role inside): receives `commission_recorded` / payment
  confirmations, writes `deal_pnl.actual_gci`, recomputes `variance`, and emits a
  **`HistoryTransactional`** event **on CDL via `cdl-write`** (the app/EF never holds
  the CDL service-role key — ADR-012) with `MajorChangeType = Actual GCI received`.
  On `|variance| > threshold` it also surfaces an `Activity` notification.
- **`finance-erp-reconcile`** (scheduled daily via `pg_cron`): flags closed
  transactions with no `actual_gci`.

EF source is committed to `matrix-pipeline-2-0/supabase/functions/` per the
[cursor-git-handoff](../../../.cursor/rules/cursor-git-handoff.mdc) rule.

**Closed-Won gating** (unchanged, [wiki/overview.md#pipeline](../../product-specs/matrix-pipeline/wiki/overview.md)):
`Property.StandardStatus = Closed` + full-payment webhook + an existing
`TransactionManagement` row + reconciliation complete.

### 4. What the engine does NOT do

No legal ledger, no invoicing, no payouts, no AI-modified commission rules/rates
(deferred with the AI Copilot). It is an **operational advisory** forecast tool, not a
system of record for money.

## KB divergence (escape-hatch, recorded — not silent)

- **Plan "C1 — add SSO permission keys `pipeline:commission:*`" is not implemented as
  written.** Justification: matrix-pipeline's authz model is `role_configurations`
  page/action keys + CDL JWT-scope, not `sso_app_permissions` (ADR-025). Writing those
  rows is dead data and implies a second, unused authz path. Divergence is in
  implementation *layer*, not in *outcome* — commission features are still role-gated.
- **Implementation-status sequencing**: this ADR records the decided architecture;
  the app-private schema + hooks + UI land via Lovable (Week-5 Prompts 2/3/4/5) and
  the two Finance-ERP EFs land via Cursor (`finance-erp-webhook` deploy + smoke is
  gated on the `deal_pnl` table existing — i.e. after the Lovable schema migration).

## Consequences

### Positive
- CDL + SSO stay clean: no economics on `transaction_management` (ADR-026 preserved),
  no dead SSO permission rows (ADR-025 preserved), no app-held CDL service-role key
  (ADR-012 preserved).
- Reconciliation audit is canonical: actuals land as a `HistoryTransactional` event on
  the same event spine as the rest of the transaction phase (ADR-026).

### Negative / notes
- Forecast/compensation are advisory; the legal ledger remains the external Finance
  ERP. Variance is informational.
- Per-`member_key` compensation attribution depends on a resolvable
  SSO-user → `member_key` mapping; until that lands (see R3 / `O-ROSTER`,
  separately-tracked), `broker_compensation` rows are owned by the acting app user.

## Alternatives considered
- **Register `pipeline:commission:*` in `sso_app_permissions`** — rejected (ADR-025;
  dead data, second authz path).
- **Model Commission Engine tables in CDL** — rejected; they are app-private advisory
  state with no RESO home and no cross-app consumer ([wiki/commission-engine.md#deviation](../../product-specs/matrix-pipeline/wiki/commission-engine.md)).
- **Add economics columns to `transaction_management`** — rejected (ADR-025/ADR-026;
  it stays the bare RESO header).
