# ADR-032: Matrix Comms — per-app SSO session storage and app_permissions

**Status**: Accepted  
**Date**: 2026-06-15  
**Apps affected**: Matrix Comms (`/comms/`, App DB `ujowkipnqgtazmtdsnlm`)

## Context

Matrix apps on `intranet.sharpsir.group` share the same browser origin. All apps historically used identical `localStorage` keys for SSO tokens (`matrix_sso_access_token`, etc.). When a user switched to a lower-privilege role inside Matrix Comms, the shared token was overwritten and other apps (e.g. ITSM) lost access until re-login.

Matrix Comms also lacked the platform template patterns for role-scoped page access: no universal landing page, no `ProtectedRoute` + `pageKey` registry, and a non-functional `role-configurations` API stub.

## Decision

### 1. Per-app SSO token namespace

Matrix Comms namespaces all SSO storage keys with a `:comms` suffix (e.g. `matrix_sso_access_token:comms`). Each app on the same origin maintains an independent active role and access token. Users still authenticate once via the shared SSO login page; only token persistence is per-app.

### 2. Role permissions via `app_permissions` (ITSM pattern)

Page/action access is stored in the Comms App DB table `app_permissions` with `app_id = 'comms'`, keyed by `(tenant_id, app_id, member_type, permission_type, permission_key)` where `member_type` is the SSO role UUID.

- Frontend reads/writes via PostgREST with SSO bearer token (Third-Party Auth on App DB).
- RLS: SELECT for authenticated same-tenant; INSERT/UPDATE/DELETE for `org_admin` / `system_admin` only.
- Admin scopes (`global`, `org_admin`, `system_admin`) bypass page checks in `useRoleConfig`.
- **Home (`/`) is excluded** from the permission registry — always available to all authenticated users.

### 3. Shared SSO identity (unchanged)

Comms continues to use the platform SSO instance (`xgubaguglsnokjyudgvc`) with its own OAuth `client_id` (`WSvfGsovutXBHJfQOdL9uPA4TnMIIVrZ`). No separate SSO server.

## Consequences

- Role switching in Comms no longer affects ITSM or other apps on the same origin.
- Other apps should adopt the same `:app-slug` storage suffix if they expose role switching on a shared origin.
- Org admins configure Comms page access in Settings → Permissions (not SSO Console page keys).
- Requires TPA provisioned on Comms App DB for PostgREST permission reads/writes.
